# WeWin 架构优化与重构计划

> 生成日期：2026-11-22
> 目标：在不丢失任何数据的前提下，清理遗留残骸、消除代码重复、拆分"上帝模块"、修复已知 Bug，并建立数据库备份机制。

---

## 一、Summary（概述）

本次重构覆盖 5 个阶段，按风险从低到高排列，每个阶段可独立验证、独立回滚：

1. **数据库备份**（前置，最高优先级）：一次性备份 + 定期备份脚本
2. **低风险清理**：删除 7 个废弃目录、补 `Pillow` 依赖、统一 JWT 认证装饰器
3. **拆分 `store` 后端上帝模块**：`models.py`(894 行) 与 `views.py`(2048 行) 按业务域拆成包，保持表名/URL/响应不变
4. **修复已知 Bug**：前端 2 处明显 bug + 路由 `requiresAdmin` 守卫缺失
5. **拆分前端巨型组件**：`Products.vue`(67KB)、`ProductTable.vue`(51KB)、`StoreTest.vue`(44KB)

**数据安全核心保障**：所有模型均显式 `db_table`，拆分只移动文件、不改变 `app_label` 与迁移历史；任何后端改动前先备份 `db.sqlite3`。

## 三、Proposed Changes（具体改动）

### 阶段 1：数据库备份（前置）

**目标**：任何代码改动前，先建立可恢复的数据快照。

1. **一次性备份**：复制 `Server/db.sqlite3` 为 `Server/db.sqlite3.bak.YYYYMMDDHHMMSS`（保留时间戳，不覆盖旧备份）。
2. **新建定期备份脚本**：创建 `Server/backup_db.py`（Python 脚本，用 `shutil.copy2` 复制数据库 + 保留最近 N 份、自动清理旧备份），并在项目根提供 `backup_db.bat`（PowerShell 调用入口）方便一键执行。
   - 脚本支持参数：`--keep 10`（默认保留最近 10 份）。
   - 备份文件命名：`db.sqlite3.bak.<时间戳>`。
   - 后续可通过 Windows「任务计划程序」挂载定时执行（计划中仅交付脚本，不自动注册系统任务，避免越权改动系统）。

**改动的文件**：
- 新增 `Server/backup_db.py`
- 新增 `backup_db.bat`（项目根）

### 阶段 2：低风险清理

**目标**：消除明显残骸与依赖缺陷，统一认证逻辑。

#### 2.1 删除 7 个废弃目录

删除 `Server/` 下的 `common` / `core` / `inventory` / `order` / `product` / `purchase` / `sales`（仅含 `.pyc` 与空 `migrations` 目录，源文件已不存在，数据库无对应表）。**已核实不在 `INSTALLED_APPS`，删除无副作用。**

#### 2.2 补 `Pillow` 依赖

在 [requirements.txt](file:///d:/workplace_shop/WeWin/Server/requirements.txt) 末尾追加 `Pillow==10.4.0`（与 `ImageField` 匹配），并在当前 `venv` 中 `pip install` 确保运行时可用（当前 venv 可能已装，需 `pip show` 核实）。

#### 2.3 统一 JWT 认证装饰器

**改动范围**：`store/views.py`、`account/views.py`、`company/views.py`。

**做法**：
- 使用已有的 [utils/decorators.py](file:///d:/workplace_shop/WeWin/Server/utils/decorators.py) 中的 `jwt_required` / `permission_required` 装饰器。
- 将每个视图内联的以下代码块替换为 `@jwt_required` 装饰器：

```python
# 删除的重复代码（每个视图都有，约 20 处）
auth_header = request.headers.get('Authorization')
if not auth_header or not auth_header.startswith('Bearer '):
    return JsonResponse({'error': '未授权'}, status=401)
token = auth_header.split(' ')[1]
try:
    payload = jwt.decode(token, SECRET_KEY, algorithms=['HS256'])
except jwt.ExpiredSignatureError:
    return JsonResponse({'error': 'Token已过期'}, status=401)
except jwt.InvalidTokenError:
    return JsonResponse({'error': '无效的Token'}, status=401)
current_user = User.objects.get(id=payload['user_id'])
```

- 视图函数签名加 `@jwt_required`，函数体内将 `current_user` 替换为 `request.user`（装饰器已把 `User` 对象挂到 `request.user`）。
- 保留 `get_platforms` / `get_categories` 这类**公开枚举接口不加装饰器**（当前它们就没有 JWT 校验，保持不变）。
- 权限判断（`if current_user.user_type in [...]`）改为 `if request.user.user_type in [...]`。

**注意**：`customer/views.py` 已使用 `authenticate_jwt` 辅助函数，本次**暂不改动**（保持行为一致、降低风险），后续可作为统一到装饰器的候选。

## 四、Assumptions & Decisions（假设与决策）

1. **数据安全优先**：任何后端改动前先执行阶段 1 备份；拆分只移动文件、不改 `db_table` / `app_label` / URL / 响应 JSON。
2. **拆分采用「app 内部包拆分」而非「拆成独立 Django app」**：避免改变 `INSTALLED_APPS`、迁移历史与表名，风险最低，且不会与已废弃的 `order`/`product` 等目录命名冲突。
3. **`customer/views.py` 的 `authenticate_jwt` 本次不改**：已能正常工作，统一到装饰器留作后续候选，避免扩大改动面。
4. **`Inventory.vue` / `Sales.vue` 占位页不在本次范围**：用户未要求新增功能，仅做结构优化与 bug 修复。
5. **备份脚本只交付脚本，不自动注册 Windows 计划任务**：避免越权修改系统配置；如需定时，由用户手动挂载。
6. **不引入 DRF、不换数据库**：保持现有手写函数视图 + SQLite 架构，只做结构整理。
