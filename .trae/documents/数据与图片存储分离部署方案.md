# 数据与图片存储分离及前后端部署方案（frp 组网版）

## Summary

采用「计算与存储分离 + frp 内网穿透」架构：

- **阿里云（2 vCPU / 2GB / 40GB，x86，公网）**：应用层 + frp 服务端（frps）——Nginx（前端静态 + 图片访问）+ Gunicorn（Django 后端）+ frps。
- **n1（armbian，ARM，128GB，无公网，内网）**：数据层 + frp 客户端（frpc）——MariaDB（业务数据库）+ SSHD（承载图片目录，经 frp 映射给阿里云）。

n1 无公网 IP，通过 frp 反向接入阿里云：MariaDB 的 3306 与 SSH 的 22 通过 frpc 映射到阿里云本机端口，Django 与 sshfs 均经阿里云本机回环访问，**不暴露公网**。

核心改动：数据库由 SQLite 迁移到 n1 上的 MariaDB；图片由阿里云本地 `Server/media` 迁移到 n1 图片目录（经 frp SSH 映射的 sshfs 挂载）。

## Proposed Changes

### 1. frp 组网（阿里云 frps + n1 frpc）

**阿里云（frps 服务端）**，`frps.toml`：
```toml
bindPort = 7000
# 将映射端口仅绑定到本机回环，避免暴露公网
proxyBindAddr = "127.0.0.1"
```

**n1（frpc 客户端）**，`frpc.toml`：
```toml
serverAddr = "<阿里云公网IP>"
serverPort = 7000

[[proxies]]
name = "mariadb"
type = "tcp"
localIP = "127.0.0.1"
localPort = 3306
remotePort = 13306

[[proxies]]
name = "ssh"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 10022
```

结果：
- MariaDB：`127.0.0.1:13306`（阿里云本机）→ n1 `3306`
- SSH：`127.0.0.1:10022`（阿里云本机）→ n1 `22`

> 说明：frp 版本以 TOML 配置为准（v0.52+）；旧版用 INI（`frpc.ini`）等价。`proxyBindAddr = "127.0.0.1"` 让映射端口只允许阿里云本机访问，Django 与 sshfs 均走回环，公网无法直接连 MariaDB/SSH。

### 2. 数据库迁移 SQLite → MariaDB（n1）

**n1 侧：**
```bash
apt update && apt install -y mariadb-server
sed -i 's/^bind-address.*/bind-address = 0.0.0.0/' /etc/mysql/mariadb.conf.d/50-server.cnf
systemctl restart mariadb
mariadb -e "CREATE DATABASE wewin CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'wewin'@'%' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON wewin.* TO 'wewin'@'%'; FLUSH PRIVILEGES;"
```
（MariaDB 监听 `0.0.0.0:3306`，由 frpc 抓取并映射；也可保持 `127.0.0.1`，frpc `localIP=127.0.0.1` 同样可达。）

**阿里云后端侧：**
- 新增依赖 `pymysql`（纯 Python，ARM 友好；`mysqlclient` 在 ARM 编译较麻烦）：
  - [requirements.txt](file:///d:/workplace_shop/WeWin/Server/requirements.txt) 追加 `pymysql==1.1.1`
- 修改 [settings.py](file:///d:/workplace_shop/WeWin/Server/wewin/settings.py)：
  - 顶部 `import pymysql; pymysql.install_as_MySQLdb()`
  - `DATABASES` 改为读取 `.env`（`DB_ENGINE/DB_NAME/DB_USER/DB_PASSWORD/DB_HOST/DB_PORT`），默认回退 SQLite（兼容本地开发）
- `Server/.env`：
  ```
  DB_ENGINE=django.db.backends.mysql
  DB_NAME=wewin
  DB_USER=wewin
  DB_PASSWORD=<强密码>
  DB_HOST=127.0.0.1
  DB_PORT=13306
  ```

**数据迁移（SQLite → MariaDB）：**
```bash
cd Server
python manage.py dumpdata --exclude auth.permission --exclude contenttypes > data.json
# 切换 .env 到 MySQL 后
python manage.py migrate
python manage.py loaddata data.json
```
> `FinishedProductCostHistory.bom_snapshot`、订单 `platform_raw_data` 等 JSONField 在 MySQL 下为 JSON 列，dumpdata/loaddata 可正常往返。

### 3. 图片存储迁移到 n1（frp SSH 映射 + sshfs 挂载）

**n1 侧：**
```bash
mkdir -p /srv/wewin/media && chown wewin:wewin /srv/wewin/media
# SSHD 默认开启；确保 wewin 用户可 SFTP
```

**阿里云侧：**
```bash
apt install -y sshfs
mkdir -p /mnt/wewin-media
# 通过 frp 映射的 SSH 端口挂载（本机回环）
sshfs -p 10022 wewin@127.0.0.1:/srv/wewin/media /mnt/wewin-media -o allow_other,reconnect
# 写入 /etc/fstab 或 systemd automount 实现开机自动挂载（推荐 systemd automount）
```

**Django 侧（改动极小）：**
- [settings.py#L137-L139](file:///d:/workplace_shop/WeWin/Server/wewin/settings.py#L137-L139)：`MEDIA_ROOT` 改为挂载点 `/mnt/wewin-media`（本地开发通过 `.env` 开关区分，仍可用 `Server/media`）。
- `MEDIA_URL` 保持 `"media/"` 不变。

**图片访问链路：** 前端请求 `http://<阿里云>:8080/media/products/xxx.jpg` → 阿里云 Nginx `/media/` 定位到 `/mnt/wewin-media`（经 frp+sshfs 读取 n1 文件）→ 返回图片；上传时 Django 经挂载点直接写 n1，无额外代码改动。

### 4. 前后端部署（阿里云，传统进程）

**后端 Gunicorn 替代 runserver：**
- [requirements.txt](file:///d:/workplace_shop/WeWin/Server/requirements.txt) 追加 `gunicorn`
- systemd 单元 `wewin-backend.service`：
  ```
  ExecStart=Server/venv/bin/gunicorn wewin.wsgi:application --bind 0.0.0.0:8003 --workers 3 --timeout 120
  ```
  （2GB 内存配 2~3 worker）

**前端 Nginx：**
- 复用/改造 [nginx_system.conf](file:///d:/workplace_shop/WeWin/nginx_system.conf)，`server` 内追加：
  ```nginx
  location /media/ {
      alias /mnt/wewin-media/;
  }
  ```
- `root` 指向 `Page/dist`（SPA `try_files` 已具备）

## Assumptions & Decisions

1. **数据库软件用 MariaDB**（MySQL 协议兼容，armbian 的 `apt` 原生提供）。
2. **Django MySQL 驱动用 `pymysql`**（纯 Python，避免 ARM 交叉编译 `mysqlclient`），通过 `pymysql.install_as_MySQLdb()` 接入。
3. **图片用 sshfs 挂载**（经 frp 的 SSH 映射）：当前图片量几乎为 0，Django 改动最小（仅改 `MEDIA_ROOT`），且走 frp 隧道较安全。图片量增大后再升级为独立图片服务/对象存储。
4. **组网用 frp**：阿里云为 frps，n1 为 frpc；映射端口仅绑定 `127.0.0.1`，Django 与 sshfs 均走阿里云本机回环，不暴露公网明文。
5. 前端继续直连后端 `8003`（`VITE_API_BASE_URL` 控制），暂不强制 nginx 反代 `/api/`，最小改动优先。

## Verification

1. **frp 连通**：n1 `frpc` 连上阿里云 `frps`；阿里云 `mysql -h 127.0.0.1 -P 13306 -u wewin -p` 可登录；`ssh -p 10022 wewin@127.0.0.1` 可登录。
2. **数据库连通与迁移**：`python manage.py check` 无 DB 报错；`migrate` 在 MariaDB 建表成功；`loaddata` 后商品/订单/客户数量与 SQLite 一致。
3. **图片上传与访问**：上传图片 → 出现在 n1 `/srv/wewin/media/products/...` → 前端 `http://<阿里云>:8080/media/...` 正常显示。
4. **前后端服务**：`systemctl status wewin-backend` active；访问 `http://<阿里云>:8080` 前端加载，登录后 API 正常。
5. **重启自愈**：阿里云与 n1 重启后，frps/frpc 自启、MariaDB 自启、sshfs 自动挂载、gunicorn/nginx 自启，应用可访问。
6. **备份**：n1 配置 MariaDB 定期 `mysqldump` 备份到 `/srv/wewin/backup`（可选 cron）。
