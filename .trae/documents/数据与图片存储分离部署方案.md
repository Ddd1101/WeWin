# WeWin 图片存储分离部署方案（N1 在线原文件版）

本方案按实际需求修订：阿里云磁盘有限，N1的主要用途是存放在线图片原文件。阿里云保留应用、SQLite与有界图片缓存；N1承担图片读写。数据库不迁移。

## 目标和数据路径

```text
Web / Android → HTTPS443 → Ali Nginx
  /        → /srv/wewin/web
  /api/    → Gunicorn127.0.0.1:8003 → Ali SQLite
  /media/  → Ali有界缓存 → 127.0.0.1:10080 → N1媒体服务18080 → N1原文件

上传 → Django校验 → 事务外写入N1 → 短事务更新SQLite图片引用
N1专用SSH客户端 → Ali22，反向映射仅监听127.0.0.1:10080
原FRP7000/6000仅保留管理通道，与媒体链路独立
```

| 数据 | 阿里云 | N1 |
| --- | --- | --- |
| 主数据库 | /var/lib/wewin/db.sqlite3 | 数据库快照 |
| 在线图片原文件 | 不长期保留 | ~/Documents/workplace_shop/wewin-media/objects/products |
| 图片缓存 | 独立2GB文件系统，淘汰目标1.5GB | 原文件直接读取 |
| 上传临时文件 | 独立512MB文件系统，最多4个并发 | 上传临时文件校验后原子发布 |
| 图片恢复 | 从N1在线文件/回收区恢复 | 7天且最多5GB回收区；暂无独立设备 |
| 云侧备份 | SQLite+媒体引用/哈希清单，暂存预算512MB | 拉取并校验备份，图片内容不再回存云侧 |

## 改造内容

独立Go媒体服务只在N1回环18080监听，无Docker/Python升级要求。服务使用独立读写凭据，限制路径、符号链接、图片类型、100MB大小与SHA-256，上传使用唯一文件名。同名同哈希重试幂等，不覆盖不同内容；删除先回收，不直接擦除在线原文件。低于5GB可用空间时拒绝新增写入。

N1使用专用SSH密钥主动连接Ali22。阿里云专用账号只能转发指定回环端口，不提供shell、密码登录或其他端口转发。原有FRP管理链路和用户定时任务保留。N1 origin与tunnel进程各有独占监督锁，开机由cron启动，5分钟检查恢复，断线keepalive和5秒重连。

Django保留本地开发存储，生产采用N1存储。上传在数据库事务外完成，数据库失败/响应丢失时保留文件并通过持久清理队列核对引用。新孤儿文件有24小时宽限期；旧文件只有确认无商品引用才移入回收区，并失效缓存。纯文字编辑保留既有SKU，避免误删BOM引用。

Nginx保留公网HTTPS入口，/media代理N1并缓存成功响应。独立文件系统控制2GB硬上限，缓存管理目标1.5GB；上传暂存也有512MB硬上限。N1失联时缓存图片可读，未缓存图片及图片写操作503，登录/订单/文字操作继续运行。新增health/core和health/media检查分开报告，不因媒体故障自动重启后端。

## 迁移和备份

部署前生成旧运行代码、生产配置和SQLite快照，报告保存在仓库外。暂停写入后，将可找到的图片复制到N1并核对文件大小和哈希。原有9条缺图引用按清单保留，不用占位图片掩盖缺失。

切换后通过真实HTTPS上传、替换、BOM展示、权限及故障恢复验证N1存储。图片原文件和历史含图备份在N1校验保留后，清理云侧全量副本。云侧备份只包含数据库、media-manifest.json和归档校验清单；预算耗尽时停止新增批次并报告故障，恢复同步后继续。

N1拉取每小时数据库快照和媒体清单，下载临时文件完整校验后才发布。联合恢复需要指定N1媒体根目录，工具从在线原文件或回收区读取图片核对哈希并还原到新目录。未提供媒体目录只能验证数据库与清单，不能声明图片已恢复。

开放新写入前可回退旧配置；开放写入后若回退，先停止图片写入并将新增/变化图片同步回来，再切换。旧数据库/媒体快照不能直接覆盖新写入。

## 验收与限制

完成标准：新上传图片原文件写入N1；阿里云图片相关空间有硬上限；失联影响按依赖隔离；备份不包含图片内容；版本、校验、迁移和恢复结果可复查。

验证包含：图片读写/替换/删除、BOM/企业隔离、断线缓存与503、业务核心正常、媒体重启/隧道重连、共享图片与孤儿清理、缓存和临时磁盘上限、联合恢复及客户端构建。

N1目前没有独立图片备份设备，回收区不能抵御设备损坏；后续独立磁盘/NAS/对象存储由同一媒体清单和同步接口承接。Android真机和跨日高峰容量没有设备或持续观察时应明确记录，不能用一次构建或短时测试代替。
