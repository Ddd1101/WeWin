# 手串成品成本监控方案：复盘与规划

## 一、概述（Summary）

**目标**：当组成手串成品（`finished`）的串珠（`bead`）/ 配件（`accessory`）成本发生变动时，自动重算所有关联成品的成本并记录快照；在成品上提供「历史最高 / 当前(当时) / 历史最低」成本的查看入口，供运营随时参考成本波动。

**范围边界（已与用户确认）**：
- 本期聚焦「成本监控」本身：变动触发重算 → 记录快照 → 查看最高/当前/最低。
- **不引入**「批次成本 / 入库批次」「基准价 / 基准售价」「售价决策联动」等扩展。
- 物料成本精度**保持 2 位小数**，不调整字段精度。

核心链路已实现并完成一轮真实环境实测。本期规划主要是**补强正确性、可追溯性与查看体验**。

## 二、现状复盘（Current State Analysis）

### 2.1 数据模型

- `FinishedProduct`（[product.py](file:///d:/workplace_shop/WeWin/Server/store/models/product.py#L141-L167)）：以 `product` 为 `primary_key`（**无 `id` 字段**），含 `labor_cost`（工费）、`elastic_cost`（弹性成本）。
- `FinishedProductBead` / `FinishedProductAccessory`（[product.py](file:///d:/workplace_shop/WeWin/Server/store/models/product.py#L205-L270)）：成品 BOM，`bead`/`accessory` 的 `related_name` 均为 `finished_products`，`sku` 可空。
- `FinishedProductCostHistory`（[product.py](file:///d:/workplace_shop/WeWin/Server/store/models/product.py#L273-L295)）：成本快照，字段为 `cost_price`（总成本）、`bead_cost`、`accessory_cost`、`labor_cost`、`elastic_cost`、`trigger_reason`、`created_at`。**无 BOM 明细、无触发人**。

### 2.2 成本计算口径

- 公式：**总成本 = 串珠小计 + 配件小计 + 工费 + 弹性成本**。
- 串珠/配件小计**优先用 SKU 的 `cost_price`**，无 SKU 时回退到 `product.cost_price`，乘以数量。
- 实现：`_finished_cost_breakdown`（[helpers.py](file:///d:/workplace_shop/WeWin/Server/store/views/helpers.py#L33-L47)）。
- 串珠单颗成本来源：`purchase_cost(克价,4位) × weight(克重,2位)`，结果落到 `cost_price`(2位) 时发生一次舍入。用户已确认保持 2 位。

### 2.3 触发链路（已接入）

| 场景 | 位置 | 动作 |
|---|---|---|
| 新建成品 | `create_product` 成品分支（[product_views.py](file:///d:/workplace_shop/WeWin/Server/store/views/product_views.py#L437-L439)） | `record_finished_cost_history(finished, '成品创建')` |
| 编辑串珠成本 | `update_product` 串珠分支（约 L639-L640） | `sync_skus` 后 `recalculate_related_finished_products(product, '串珠「xx」成本变更')` |
| 编辑配件成本 | `update_product` 配件分支（约 L661-L662） | 同上，`'配件「xx」成本变更'` |
| 编辑成品（工费/弹性/BOM） | `update_product` 成品分支（约 L737-L739） | `record_finished_cost_history(finished, '成品成本核算')` |

关键函数（[helpers.py](file:///d:/workplace_shop/WeWin/Server/store/views/helpers.py)）：
- `record_finished_cost_history`：只记变化（上次 `cost_price`/`labor_cost`/`elastic_cost` 相同则不记录）。
- `recalculate_related_finished_products`：按物料 `product_type` 收集关联成品，逐个重算 + 更新 `finished.product.cost_price`。
- `finished_cost_summary`：返回 `highest_cost / current_cost / lowest_cost`（无记录时为三个 `None`）。

### 2.4 展示与入口

- 后端 `get_products` / `get_product_detail` 成品分支返回 `finished.cost_summary`（[product_views.py](file:///d:/workplace_shop/WeWin/Server/store/views/product_views.py#L197-L198) 与 L943-L944）。
- 前端 [ProductTable.vue](file:///d:/workplace_shop/WeWin/Page/src/views/components/ProductTable.vue#L105-L109)（桌面+手机端）成品展开区新增 `.cost-monitor` 三色行：历史最高（红）/ 当前成本（深灰）/ 历史最低（绿）。

### 2.5 初始化

- 管理命令 `init_finished_cost_history`（[init_finished_cost_history.py](file:///d:/workplace_shop/WeWin/Server/store/management/commands/init_finished_cost_history.py)）：为现有成品回填初始快照，已回填 26 条。

## 三、复盘发现的问题与缺口

1. **【P0 一致性】`update_product` 无事务包裹**：`create_product` 已用 `transaction.atomic()`，但 `update_product` 没有。物料更新成功后，`recalculate_related_finished_products` 若中途失败，会导致部分成品已重算、部分未重算，成本快照与 `product.cost_price` 不一致。

2. **【P1 可追溯】快照缺 BOM 明细与触发人**：`FinishedProductCostHistory` 只存金额小计，无法回答「当时的成本是由哪些串珠/配件、什么单价、多少数量算出来的」；也无 `created_by` 记录是谁改的。

3. **【P1 可追溯】“只记变化”判断不完整**：当前只比较 `cost_price`/`labor_cost`/`elastic_cost`。若串珠小计上升、配件小计等额下降导致总成本不变，会漏记这次组成变化。

4. **【P1 查看体验】入口只有汇总三值**：无「成本历史列表」入口，用户看不到逐次快照的时间、触发原因、变化幅度与明细。

5. **【P2 边界】删除物料导致成品 BOM 与成本不一致**：`delete_product` 是硬删除（`product.delete()`，[product_views.py](file:///d:/workplace_shop/WeWin/Server/store/views/product_views.py#L814)）。删除被成品引用的串珠/配件会级联删除 BOM 行，但**不会重算**关联成品成本。

6. **【P2 清理】死代码**：`calculate_finished_product_cost`（[helpers.py](file:///d:/workplace_shop/WeWin/Server/store/views/helpers.py#L5-L30)）已无任何引用（`product_views.py` 的 import 已移除），可删除或保留，仅作清理项。

## 四、规划补强（Proposed Changes）

### P0 — 事务一致性（必做）

**文件**：`Server/store/views/product_views.py` 的 `update_product`（约 L487 起）。

**改法**：给 `update_product` 函数增加 `@transaction.atomic` 装饰器（`transaction` 已在文件顶部导入），使「物料/SKU 更新 → 重算关联成品 → 记录快照 → 更新成品 `cost_price`」整体原子化。若担心装饰器影响其它分支，也可仅在 bead/accessory/finished 三个分支内用 `with transaction.atomic():` 局部包裹重算逻辑。

### P1 — 快照可追溯：增加触发人与 BOM 明细

**文件**：
1. `Server/store/models/product.py` 的 `FinishedProductCostHistory`：
   - 新增 `created_by = models.ForeignKey(User, on_delete=models.SET_NULL, null=True, blank=True, related_name='finished_cost_histories', verbose_name='触发人')`。
   - 新增 `bom_snapshot = models.JSONField(default=dict, blank=True, verbose_name='BOM快照')`。
2. 生成迁移：`python manage.py makemigrations store`（命名如 `0017_...`）。

**改法**：`record_finished_cost_history(finished, trigger_reason='', created_by=None)` 增加参数并在创建快照时写入：
- `bom_snapshot` 结构（串珠/配件明细，含货号、SKU、数量、单价、小计）：
```json
{
  "beads": [{"code": "草莓晶", "sku_code": "草莓晶-10M", "quantity": 7, "unit_cost": 0.75, "subtotal": 5.25}],
  "accessories": [{"code": "花边葫芦", "sku_code": "花边葫芦", "quantity": 1, "unit_cost": 1.5, "subtotal": 1.5}]
}
```
- 优化「只记变化」判断：同时比较 `bead_cost`/`accessory_cost`（或对 `bom_snapshot` 做相等比较），避免总成本不变但组成变化时漏记。

**调用处传参**：
- `recalculate_related_finished_products(..., created_by=None)` 透传给 `record_finished_cost_history`。
- `update_product` / `create_product` 中传 `request.user`。
- 管理命令 `init_finished_cost_history` 传 `created_by=None`。

### P1 — 后端：成品成本历史列表接口

**文件**：`Server/store/views/product_views.py` + `Server/store/urls.py`。

**改法**：
- 新增视图 `get_finished_cost_history(request, product_id)`（`@jwt_required` + `@require_http_methods(['GET'])`），校验权限后返回该成品 `cost_history` 列表（按 `created_at`/`id` 正序），每条含 `id`、`cost_price`、`bead_cost`、`accessory_cost`、`labor_cost`、`elastic_cost`、`trigger_reason`、`created_by_name`、`created_at`、`bom_snapshot`。
- 注册路由：`path('products/<int:product_id>/cost-history/', views.get_finished_cost_history, name='get-finished-cost-history')`（放在 `products/<int:product_id>/detail/` 附近，避免与 `update/delete` 的 `<int:product_id>` 冲突，路径更具体优先匹配即可）。

### P1 — 前端：成本历史详情入口

**文件**：
1. 新增 `Page/src/views/components/FinishedCostHistoryDialog.vue`：弹窗展示成本历史时间线/列表（时间、总成本、串珠/配件/工费/弹性小计、触发原因、触发人、较上次变化幅度），可选展开 BOM 明细。
2. `Page/src/views/components/ProductTable.vue`：在成品展开区 `.cost-monitor` 旁新增「成本历史」按钮（桌面+手机端），点击打开弹窗并调用成本历史接口；新增对应 `store` API 客户端方法（`Page/src/api/store.js` 中追加 `getFinishedCostHistory(productId)`）。

### P2 — 删除物料边界处理

**文件**：`Server/store/views/product_views.py` 的 `delete_product` + 前端删除确认。

**改法（二选一，建议 A）**：
- **A（推荐，轻量）**：在 `delete_product` 中，若被删商品是 `bead`/`accessory` 且存在 `finished_products` 引用，则先对其关联成品执行 `recalculate_related_finished_products` 重算并记录快照，再删除；或直接返回提示「该物料正被 N 个成品使用，无法删除」。
- **B（更强约束）**：把 `FinishedProductBead.bead` / `FinishedProductAccessory.accessory` 的 `on_delete` 由 `CASCADE` 改为 `PROTECT`，从模型层禁止删除被引用物料（需迁移）。

> 注：P2 与「成本监控」核心目标相关度较低，可后续单独处理，本次规划先记录方案，视优先级再实施。

### P2 — 清理死代码（可选）

**文件**：`Server/store/views/helpers.py` 的 `calculate_finished_product_cost`。

**改法**：确认无引用后删除（`_finished_cost_breakdown` 已覆盖其能力）。仅清理，不影响功能。

## 五、假设与决策（Assumptions & Decisions）

- **范围** = 成本监控（变动触发 → 记录 → 查看最高/当前/最低），不扩展批次/基准价/售价。
- **成本精度** = 保持 2 位小数。
- **触发入口** = 复用「编辑商品」（`update_product`），保存时自动触发（已确认）。
- **记录时机** = 只记变化（成本或组成实际变化才记录）（已确认）。
- **“当时成本”语义** = 当前/最新一次成本（即 `cost_summary.current_cost`），与历史最高/最低并列展示。
- **删除边界（P2）** 本期先出方案，是否实施待用户确认。
